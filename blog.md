## 2026-07-24 — Static site replacement design

- Goal: replace the static site's surrounding interface while preserving its manual data, corrected-text editing, bounding-box editing, JSON download, and GitHub submission behavior.
- The existing warm archive-like palette and a more colorful fan-site direction were both rejected. Settled on a precision-utility interface with subtle Japanese product-catalog influence, a cool light-gray workspace, highly readable proportional type, and deep Sentai red as the single primary accent.
- The home page remains a visual catalog, but with less hero space, larger consistent manual artwork, quieter metadata, neutral tags with small color markers, and the existing dry tagline unchanged.
- The manual viewer becomes reading-first: full-width continuous pages, corrected text on by default, one corrected-text toggle, compact page controls, and editing behind an explicit action.
- Phones are read-only. Editing requires a viewport at least 1024 CSS pixels wide and a fine pointer, which also permits capable landscape tablets.
- Editing keeps the current text and normalized X/Y/Width/Height controls, adds direct drag/resize handles, an optional all-translations drawer, multi-step undo/redo, and versioned per-manual local draft recovery.
- Undo/redo history and draft envelopes are browser-only. The JSON copied into GitHub or downloaded remains a fresh serialization of the existing manual document and never carries edit history or draft metadata.
- Corrected text must use actual proportional-font measurements and automatically choose the largest size that fits each saved box. Print has a strict 9pt minimum with about 1.15 line height. Text is never silently clipped or shrunk below that floor; unresolved blocks are linked from a warning and can still be printed through an explicit Print anyway action.
- Print is optimized for Firefox and A4. It preloads every lazy page, uses one source page per sheet, selects portrait or landscape from the source image where supported, preserves the whole page without cropping, and prints only the manual image plus opaque white corrected-text blocks. No site chrome, page labels, footer, editing state, or links appear.
- A first-run Firefox preflight reminds the user to select A4, disable headers/footers, enable backgrounds, and use one page per sheet. These print-dialog settings cannot be forced by the site.
- Tech Blog links are removed from the UI but may remain in generated metadata. Original PDF stays near the manual title; GitHub, demo, and Temporal links move to a compact home-page footer.
- The frontend remains framework-free and dependency-light. The redesign ships as one complete replacement rather than a visible staged or feature-flagged rollout.
- The implementation contract is recorded in `spec.md`, including component boundaries, TDD targets, Firefox print cases, and behavior-preservation acceptance criteria.
